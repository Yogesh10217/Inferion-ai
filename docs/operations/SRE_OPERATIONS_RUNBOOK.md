# SRE Operations Runbook

## Overview

This runbook establishes standard operating procedures for Site Reliability Engineering (SRE) on the Enterprise AI Platform. It defines operational workflows, telemetry monitoring, incident escalation, and manual intervention boundaries.

## Evidence Taxonomy & Classification

All operational evidence collected by the platform is tagged with explicit evidence classification levels:

- `STATIC`: Code and configuration analysis evidence.
- `UNIT_TEST`: Automated unit test outputs.
- `INTEGRATION_TEST`: Multi-component integration test outputs.
- `ASGI_RUNTIME`: ASGI server simulation runtime outputs.
- `SIMULATION_RUNTIME`: Simulated container/cluster runtime metrics.
- `CONTAINER_RUNTIME`: Real Docker container execution telemetry.
- `INFRASTRUCTURE_RUNTIME`: Multi-node staging/pre-prod infrastructure telemetry.
- `PRODUCTION_RUNTIME`: Live production environment runtime telemetry.

> [!IMPORTANT]
> Live production statuses MUST remain `NOT_EXECUTED` until real production infrastructure is connected and empirically tested.

## Operator Standard Procedures

1. **Daily Operational Checks**:
   - Inspect `OperationalDashboardSnapshot` via `/health` and Prometheus metrics.
   - Verify SLO statuses (`MET` vs `AT_RISK` vs `BREACHED`).
   - Monitor remaining Error Budget (Healthy >= 50%, Warning >= 20%, Critical < 20%, Exhausted = 0%).
2. **Alert Triaging**:
   - Deduplicated alerts are identified by SHA-256 fingerprints.
   - Investigate root cause before taking corrective action.
3. **Recovery Execution**:
   - Recovery decisions generated by `RecoveryDecisionEngine` are advisory ONLY (`auto_execution_blocked = True`).
   - Operators must manually review and authorize any production rollback, restart, or traffic shift.
